# marky-mark: benchmarking MarkLLM watermarks on one LLM

Take one Hugging Face causal language model, watermark it six different ways with the
[MarkLLM](https://github.com/THU-BPM/MarkLLM) toolkit, and compare the watermarked "versions" on
detectability, text quality (perplexity, diversity), standard benchmarks (BLEU on WMT16 de-en, ROUGE on
CNN/DailyMail, optionally accuracy on GSM8K and pass@1 on HumanEval) and speed. Built for a GPU cluster (SLURM, offline compute
nodes) with a narrated Jupyter notebook on top.

| variant | family | detection score | paper |
|---|---|---|---|
| `none` | unwatermarked baseline (same prompts, same sampling) | - | - |
| `KGW` | green-list logit bias | z-score | Kirchenbauer et al., ICML 2023, [2301.10226](https://arxiv.org/abs/2301.10226) |
| `MorphMark` | adaptive green-list probability shift | z-score | Wang et al., ACL 2025, [2505.11541](https://arxiv.org/abs/2505.11541) |
| `PF` | Permute-and-Flip keyed decoder | -log10 p (Gamma tail) | Zhao, Li, Wang, ICLR 2025, [2402.05864](https://arxiv.org/abs/2402.05864) |
| `SynthID` | SynthID-Text tournament sampling | mean g-value | Dathathri et al., Nature 2024, [doi](https://doi.org/10.1038/s41586-024-08025-4) |
| `SIR` | semantic invariant robust logit bias | mean bias similarity | Liu et al., ICLR 2024, [2310.06356](https://arxiv.org/abs/2310.06356) |
| `SemStamp` (optional) | sentence-level semantic rejection sampling | z-score | Hou et al., NAACL 2024, [2310.03991](https://arxiv.org/abs/2310.03991) |

The placeholder model is `facebook/opt-1.3b` (MarkLLM's reference model). Swap it via `--model`,
`WMBENCH_MODEL`, or the first config cell of the notebook.

## Results of this study

The runs behind the paper are committed under `run_results/` (copied from the cluster's `results/`):

| directory | run | contents |
|---|---|---|
| `run_results/opt13b/` | `scripts/slurm/all_in_one_robustness.sbatch`, OPT-1.3B, oracle OPT-2.7B | **the reported run**: clean detection, quality, speed, and the word-deletion and DIPPER attacks |
| `run_results/opt13b_clean/` | the same configuration without the attack stage | an earlier run; its clean results are identical to `opt13b/` |

Start with `run_results/opt13b/summary.md`. The per-sample records (`generations/`, `attacks/`,
`detection/`, `quality/`) let every number be recomputed with `--stage report`. The paper's tables,
figures and quoted numbers come from

```bash
python scripts/paper_assets.py --run run_results/opt13b --out paper --compile
```

which writes `paper/tables/`, `paper/figures/`, `paper/numbers.json` (clean detection, quality, cost),
`paper/numbers_robustness.json` (statistics under attack) and a gallery `paper/preview.pdf`. The
context-survival and SIR-truncation statistics load the generator and SIR-embedder tokenizers from the
Hugging Face hub (or `HF_HOME`) and are skipped with a warning when these are unavailable.

## Quickstart

### 1. Environment (Python >= 3.10)

```bash
python -m venv .venv && source .venv/bin/activate
pip install torch --index-url https://download.pytorch.org/whl/cu124   # pick your CUDA build / cluster module
pip install -r requirements.txt
pip install -e .            # optional: `wmbench` console script
```

Verified with torch 2.10 / transformers 5.3 / Python 3.12 (CPU + Apple MPS smoke tests); lower bounds are
torch 2.1 and transformers 4.45. MarkLLM itself is **not** installed from PyPI: the `markllm` wheel is
stale and lacks MorphMark, PF, SynthID and SemStamp. `wmbench.bootstrap.ensure_markllm()` clones the
repository at a pinned commit into `third_party/MarkLLM` on first use.

### 2. Prefetch assets (on a node with internet)

```bash
export HF_HOME=/path/to/shared/hf_cache
python scripts/prepare_assets.py --model facebook/opt-1.3b --oracle facebook/opt-2.7b   # add --semstamp if needed
```

This fetches MarkLLM (datasets ship inside it), the SIR transform network and embedder (1.3 GB) into
`artifacts/sir/`, NLTK tokenizer data, and the generator/oracle weights into the HF cache. Compute nodes
then run with `HF_HUB_OFFLINE=1` (the SLURM scripts set this).

### 3. Smoke test (minutes, CPU is fine)

```bash
python scripts/run_benchmark.py --preset smoke
```

Runs `facebook/opt-125m` on 8 C4 / 6 WMT16 / 4 CNN-DM prompts through all five watermarks and writes
`results/smoke/summary.md`. Numbers from this preset are meaningless; it validates the pipeline.

### 4. Full run

One GPU job, everything:

```bash
MODEL=facebook/opt-1.3b ORACLE=facebook/opt-2.7b RUN=opt13b sbatch scripts/slurm/single_job.sbatch
```

or equivalently

```bash
python scripts/run_benchmark.py --preset full --model facebook/opt-1.3b --oracle facebook/opt-2.7b --run-name opt13b
```

Array job (one variant per task, then a merge job):

```bash
JOBA=$(MODEL=facebook/opt-1.3b RUN=opt13b sbatch --parsable scripts/slurm/array_generate.sbatch)
MODEL=facebook/opt-1.3b ORACLE=facebook/opt-2.7b RUN=opt13b sbatch --dependency=afterok:$JOBA scripts/slurm/merge.sbatch
```

With the robustness track, `scripts/slurm/attack.sbatch` runs between the two (see "Robustness attacks").

Every stage is resumable: re-submitting continues from the cached JSONL records. A results directory
belongs to one *data-producing* configuration (model, seed, generation lengths, prompt settings, the
contents of `configs/watermarks/*.json` and any overrides; hashed into `manifest.json`); which variants,
datasets or sample counts a job runs, the device preference, and the reporting knobs may differ between
jobs that share it. A mismatch is refused unless `--force-new-run`. Cached records additionally carry the
effective hyperparameters and the prompt hash of the variant that produced them, so editing a JSON file
regenerates exactly the affected records. Results land in
`results/<run-name>/` (`summary.md`, `summary.csv`, `detection_summary.csv`, `quality_summary.csv`,
`paired_deltas.csv`, `degradation.csv`, `plots/`, per-sample `generations/`, `detection/`, `quality/`,
`manifest.json`, `logs/`).

### 4b. Qwen2.5 run with GSM8K (one submission)

`scripts/slurm/qwen_full.sbatch` runs the whole study on `Qwen/Qwen2.5-1.5B-Instruct` (bf16) with
`Qwen/Qwen2.5-7B-Instruct` as perplexity oracle: all five watermarks plus `none`, C4 / WMT16 /
CNN-DailyMail, 500 GSM8K math problems, and the word-deletion and DIPPER attacks. Submit it from the repo
root on the cluster:

```bash
git pull && sbatch scripts/slurm/qwen_full.sbatch
```

It takes roughly 15-18 h on one L40S. Fifteen minutes before the 20 h limit it resubmits itself (at most
three times) and resumes from the cached records. At the end it packs the run into
`~/wmbench/results/qwen15b-<timestamp>.tar.gz` and prints the `scp` command to download it. The headline
file is `degradation.csv`: per task and watermark the unwatermarked value, the watermarked value and the %
change with a paired bootstrap 95% CI (also a section of `summary.md`).

### 5. Notebook

`notebooks/watermark_benchmark.ipynb` walks through setup, one demo section per watermark (mechanism,
hyperparameters, a generated sample with its detection scores), the four stages, and the result tables and
plots. It defaults to the smoke preset; set `SMOKE_TEST = False` in the config cell or run it headlessly:

```bash
WMBENCH_SMOKE_TEST=0 WMBENCH_MODEL=facebook/opt-1.3b WMBENCH_ORACLE=facebook/opt-2.7b \
jupyter nbconvert --to notebook --execute --ExecutePreprocessor.timeout=-1 \
  --output executed.ipynb notebooks/watermark_benchmark.ipynb
```

(`scripts/slurm/notebook.sbatch` does exactly this.) With a virtualenv, register it as a kernel once
(`python -m ipykernel install --user --name wmbench`) and add `--ExecutePreprocessor.kernel_name=wmbench`;
if a user-level Jupyter config pulls in extensions that are not installed in the venv, point
`JUPYTER_CONFIG_DIR` at an empty directory for the run. The notebook is generated from
`scripts/build_notebook.py`; edit that file and rebuild rather than editing cells by hand.

## Pipeline and stages

| stage | what it does | parallelisable |
|---|---|---|
| `generate` | for each (dataset, variant): format prompt, generate with a per-sample seed, time it, cache | yes: `--variants X` per array task |
| `attack` | (`--robustness`) for each attack and watermark variant on C4: attack the common-budget watermarked text of every sample, record strength metrics; one attacker loaded at a time | needs the `none` and the variants' generations; DIPPER needs a 40 GB+ GPU |
| `detect` | for each watermark variant on C4: score its own, the human and the `none` continuation of every sample at one common token budget (the shortest of the three, at most `max_new_tokens`), plus the `attacked:<name>` texts from stage `attack` | needs the `none` and the variant's generations; `--variants X` per task works |
| `quality` | PPL with the oracle (generator freed first), diversity, BLEU, ROUGE, pass@1, GSM8K accuracy | needs generations |
| `report` | pure pandas over the JSONL files | any node (same device type as the run, see below) |

Detection on CPU and CUDA is **not** interchangeable: MarkLLM seeds `torch.Generator(device=...)` and the
two streams differ, so the runner refuses to touch a results directory produced on another device type
or dtype unless `--allow-device-mismatch` is passed (fine for smoke tests, wrong for results). Environment
variables (`WMBENCH_*`, see `BenchmarkConfig.from_env`) are applied on top of `--preset`; explicit flags win;
`--config <file>` is a frozen snapshot that ignores both.

## Metrics

| metric | definition | where |
|---|---|---|
| PPL | `exp(NLL)` of the C4 continuation *conditioned on its prompt* under the oracle (`facebook/opt-2.7b` by default; `none` scores with the generator). Corpus PPL = token-weighted; median per sample also reported. A `human` row scores the human continuation the same way. | `quality/c4` |
| diversity | `prod_{n=2..4}(1 - rep_n)`, `rep_n` = repeated n-gram fraction (Su et al. 2022); MarkLLM's `log_diversity` formula is reported alongside (it divides the fractional `rep_n` by 100, so it is roughly `-log(sum rep_n) + 4.6`) | `quality/c4` |
| BLEU | sacreBLEU corpus BLEU of the post-processed answer vs the WMT16 reference (first line, `German:` cue stripped); mean sentence BLEU + CI too | `quality/wmt16_de_en` |
| ROUGE-1/2/L | `rouge_score` F-measure with stemming vs CNN/DailyMail highlights (first paragraph of the answer) | `quality/cnn_dailymail` |
| pass@1 | HumanEval unit tests executed in a subprocess with a timeout (optional; `--datasets ...,humaneval`) | `quality/humaneval` |
| GSM8K accuracy | share of math problems whose final number (last `\boxed{}`, else after `####`, else the last number) equals the gold answer; zero-shot chain-of-thought prompt; test split from OpenAI's repository at a pinned commit (optional; `--datasets ...,gsm8k`) | `quality/gsm8k` |
| % change vs `none` | `mean(variant) / mean(none) - 1` on the same prompts with a paired bootstrap 95% CI; for perplexity the ratio of geometric means | `degradation.csv`, `paired_deltas.csv` |
| AUROC | watermarked vs negative scores; negatives = human C4 continuations (`_human`) or `none` generations (`_none`) | `detection_summary.csv` |
| TPR@1%FPR, TPR@5%FPR | threshold = the score exceeded by at most 1% (5%) of negatives; needs >= 100 negatives, flagged otherwise | idem |
| best F1 | max F1 over thresholds (MarkLLM's `rule='best'`) | idem |
| fixed-threshold TPR/FPR | each algorithm's shipped threshold (`z=4` KGW, `z=2` MorphMark, p<0.01 PF, 0.52 SynthID, 0.2 SIR) | idem |
| attacked TPR (`attacked_tpr_<attack>`) | attacked watermarked C4 texts scored at the threshold fixed on the clean human negatives at 1% FPR; also AUROC vs clean human text and TPR at the shipped threshold (`--robustness`) | idem |
| attack strength | per attack: `attack_len_ratio` (attacked tokens / budget), `attack_bleu_vs_source` (sacreBLEU vs the clean text; low = heavy rewriting), `attack_sim_embed` (sentence-embedding cosine similarity; high = meaning preserved) | idem |
| tok/s | continuation tokens / wall-clock generation seconds (batch size 1, untimed warm-up) | `quality_summary.csv` |

**Length control.** Detection scores accumulate evidence per token, so a watermarked text that stopped
at 80 tokens must not be compared with a 200-token human text. For every sample the watermarked, the human
and the `none` text are therefore scored at one common budget
`T = min(max_new_tokens, |watermarked|, |human|, |none|)` (token counts as the detector re-tokenises them;
each text is cut to its first `T` tokens). `T` is determined per variant because it depends on that
variant's own continuation lengths, and is stored as `detect_tokens` in every detection row; attacked
texts are derived from the truncated watermarked text and capped at `T` tokens. Samples with `T < min_detect_tokens` (50) are
excluded from that variant's detection numbers (`n_gen_ok` vs `n_samples_kept` in `detection_summary.csv`;
`pos_tokens_mean` and `neg_tokens_mean_*` show the resulting equal lengths, up to a token at the cut
boundary where the tokenizer's decode/encode round trip can re-segment a word). Detector failures on
degenerate texts are recorded as NaN and counted, and bootstrap 95% CIs are given for the key numbers.
Paired differences vs `none` on identical prompts (`paired_deltas.csv`) are the most sensitive comparison.

## Robustness attacks (`--robustness`)

Stage `attack` rewrites the watermarked C4 texts and stage `detect` scores the result as `attacked:<name>`
rows; the report answers "how much detectability survives" (`attacked_tpr_<name>` at the clean 1% FPR
threshold, `attacked_auroc_human_<name>`, `attacked_fixed_thr_tpr_<name>`) next to "how strong was the
attack" (`attack_len_ratio_<name>`, `attack_bleu_vs_source_<name>`, `attack_sim_embed_<name>`). Negatives
stay clean: a deployed threshold is calibrated on unattacked text.

| attack | what it does | cost |
|---|---|---|
| `word_deletion` | drops each word independently with probability `word_deletion_ratio` (0.3); MarkLLM's `WordDeletion` rule, seeded per sample | none |
| `dipper` | DIPPER paraphraser (Krishna et al. 2023, [2303.13408](https://arxiv.org/abs/2303.13408)): `kalpeshk2011/dipper-paraphraser-xxl` rewrites the text sentence by sentence, conditioned on the C4 prompt and the paraphrase so far, with MarkLLM's `DipperParaphraser` defaults (lexical diversity 60, order diversity 0, one sentence per window, `top_p 0.75`); re-implemented in `wmbench/attacks.py` so MarkLLM's evaluation module (OpenAI / `translate` imports) is not needed | T5-XXL, ~22 GB in bf16: a 40 GB+ GPU and a few hours for 500 x 6 texts |

Every attack row (`attacks/<dataset>/<attack>/<variant>.jsonl`) is derived from exactly the text scored
clean (the watermarked continuation cut to the sample's budget `T`), is capped at `T` tokens so a longer
paraphrase cannot add evidence (`n_tokens_uncapped` keeps the original length), carries a per-sample seed
`stable_seed(seed, "attack", <attack>, <dataset>, <sample>)` that is identical across variants, and an
`attack_config_hash` (model id, Hub revision, settings) so changed settings regenerate exactly the affected
rows. `attack_sim_embed` uses `attack_similarity_model` (`sentence-transformers/all-MiniLM-L6-v2`; `null`
when the model is not available). Settings: `--attacks`, `--dipper-model`, `dipper_lex_diversity`,
`dipper_order_diversity`, `dipper_sent_interval`, `dipper_dtype` (auto = bf16 on CUDA), all outside the run
hash. Prefetch on a node with internet: `python scripts/prepare_assets.py --model ... --oracle ... --dipper`.
The smoke preset runs `word_deletion` only.

## Fairness: what is shared and what is not

* **Shared** by every variant: prompt token ids (BOS handled identically, chat template if the tokenizer has
  one), `max_new_tokens`, natural stopping at EOS, one common per-sample detection length for the
  watermarked / human / `none` texts (see "Length control" above), and plain multinomial sampling
  `temperature=1, top_p=1, top_k=0`. Temperature 1 is the only setting under which KGW/SIR (bias added before
  HF's temperature warper), MorphMark/SynthID (return log-probs of a reweighted distribution) and PF (its own
  decoder) sample from the same base distribution, so it is not configurable.
* **Deviations forced by MarkLLM's implementations**, handled in `wmbench/watermarks.py`:
  * SynthID's processor keeps its context history across prompts; it is reset before every generation. Its
    internal temperature is pinned to 1 (it reads the value from an attribute, not from `gen_kwargs`).
  * PF's decoding loop re-encodes the prompt without BOS, samples from fp16 logits and truncates at the first
    EOS after the fact; a subclass feeds it the shared ids, fp32 logits, and stops at EOS. Its detection score
    is converted to a Gamma-tail p-value with the correct degrees of freedom.
  * SIR's token mapping is vocabulary-size specific; MarkLLM would silently create an unseeded random one for
    unknown vocabularies. A seeded mapping is generated and persisted instead, and the CUDA-pinned
    checkpoint is re-saved for CPU hosts.
  * SemStamp is OPT-only, hard-codes temperature 0.7 and a repetition penalty and suppresses EOS in MarkLLM;
    the subclass uses the shared prompt ids and sampling settings, keeps EOS, bounds the continuation by the
    shared token budget and accepts the last candidate after `N_max` rejections (the paper's fallback).
  * `min_new_tokens` and `no_repeat_ngram_size` from MarkLLM's examples are not used: PF ignores them.
  * The model's hub `generation_config.json` (repetition penalties, extra EOS ids, ...) is discarded except
    for the token ids when the model is loaded, and the resulting stop set is shared by every variant; the
    discarded fields are logged. Otherwise the HF-generate variants would inherit hub defaults that PF's own
    decoder never sees.

## Adding a model or a variant

* **Model**: any `AutoModelForCausalLM` (Hub id or local path). Pass `--model`; choose an oracle larger than
  it (`--oracle`) or `--oracle none`. `vocab_size` given to MarkLLM is the logit dimension
  (`wmbench.models.logits_vocab_size`). Chat models are prompted through their chat template (prefetch the
  template file with `prepare_assets.py` on offline clusters; the manifest records whether one was used);
  base models get few-shot / cue prompts (`wmbench/data.py`). With a foreign-family oracle the chat markup is
  scored as literal context.
* **Hyperparameters**: edit `configs/watermarks/<name>.json` or pass overrides
  (`BenchmarkConfig(watermark_overrides={"KGW": {"delta": 1.0}})`; JSON config via `--config`).
* **Variant**: add a `VariantSpec` to `wmbench/watermarks.py` (MarkLLM algorithm key, config file, score
  name, threshold) and copy the JSON from `third_party/MarkLLM/config/`. Algorithms that expose a
  `logits_processor` need nothing else; algorithms with a custom decoding loop need an adapter like `_pf_generate_from_ids`.

## Caveats

* Numbers from the smoke preset are meaningless by construction (tiny model, 8 prompts).
* BLEU/ROUGE with a base model are low in absolute terms; use the paired deltas vs `none`, or an instruct model.
* Log-likelihood benchmarks (MMLU-style multiple choice) are invariant to decoding-time watermarks and are
  therefore not included; generation benchmarks (translation, summarisation, code) are.
* `TPR@1%FPR` needs at least 100 negatives; the full preset uses 500 C4 prompts.
* Prompts that do not fit the model context with `max_new_tokens` are recorded as `ContextOverflow` errors
  (never silently truncated); CNN/DailyMail articles are cut to `article_max_words` before templating and
  the record's `prompt_truncated` flag says so.
* SemStamp is slow (up to `N_max` generations per sentence) and only evaluated on C4.
* MarkLLM is Apache-2.0; the small subclasses in `wmbench/watermarks.py` derive from it.
